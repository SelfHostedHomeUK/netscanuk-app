# Netscan

**OpenVAS-powered network vulnerability scanning with AI analysis.**

Netscan is a self-hosted web application that runs a full OpenVAS vulnerability scan against a target IP address or network range and returns a prioritised, plain-English security report generated by Claude AI. It was built to make professional-grade network scanning accessible without expensive tooling or a security background.

-----

## What it does

Enter a target IP address or CIDR range. Netscan runs a Full and Fast OpenVAS scan — 176,000+ vulnerability tests across every open port it finds — then sends the results to Claude for analysis. You get back a structured report covering:

- **Executive Summary** — plain English risk overview for a non-technical audience
- **Technical Analysis** — findings grouped by severity with attack vectors explained
- **Attack Path Analysis** — the most likely route an adversary would take
- **Remediation Plan** — prioritised fixes with effort estimates
- **Priority Next Action** — the single most important thing to fix right now
- **Downloadable Report** — full report as a Markdown file
- **Downloadable Remediation Script** — a reviewed, commented bash script to address findings

> **A thorough scan takes 30–45 minutes.** That’s not a bug — OpenVAS is running 176,000+ vulnerability tests. The UI shows real progress, lets you close the tab and resume later, and separates the scan phase from the AI analysis phase clearly.

-----

## How it works

```
Browser → Netscan (Node.js/Express)
            ├── Creates OpenVAS target + task via GMP socket
            ├── Polls scan status every 5 seconds
            ├── On completion, fetches results via get_results
            └── Sends findings to Claude API for analysis
```

Netscan runs as a Docker container alongside the Greenbone Community Edition stack. The `ospd-openvas` container is given its own LAN IP via a macvlan network so it can reach devices on your local network directly.

## Prerequisites

- A Linux server (tested on Ubuntu 24.04)
- [Greenbone Community Edition](https://github.com/greenbone/community-containers) installed and running via Docker Compose
- An [Anthropic API key](https://console.anthropic.com)
- Docker and Docker Compose

> **Note:** The initial Greenbone Community Edition setup pulls several large container images and can take a while depending on your connection. Follow the [Greenbone setup guide](https://greenbone.github.io/docs/latest/) first, then return here to add Netscan.

## Installation

### 1. Clone the repo

```bash
git clone https://github.com/SelfHostedHomeUK/netscanuk-app.git
cd netscanuk-app
```

### 2. Create the macvlan network

Netscan requires a macvlan network so the OpenVAS scanner container gets its own LAN IP address and can reach devices on your network directly.

Replace `eth0` with your server’s network interface (check with `ip route | grep default`) and adjust the IP range to match your LAN subnet:

```bash
docker network create \
  --driver macvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  --opt parent=eth0 \
  greenbone-scan-net
```

### 3. Set up the environment file

```bash
cp app/.env.example app/.env
```

Edit `app/.env` and add your Anthropic API key:

```env
ANTHROPIC_API_KEY=your_key_here
GVM_USER=admin
GVM_PASS=your_openvas_admin_password
PORT=3004
```

### 4. Add the netscan service to your Greenbone compose file

Add the following service block to your existing Greenbone `compose.yaml`, just before the `networks:` section:

```yaml
  netscan:
    build: ./netscanuk-app/app
    restart: always
    ports:
      - "0.0.0.0:3004:3004"
    env_file:
      - ./netscanuk-app/app/.env
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    depends_on:
      - gvmd
      - ospd-openvas
    networks:
      - default
```

Also update the `ospd-openvas` service in your compose file to join the macvlan network and add the `Consider Alive` workaround. Your `ospd-openvas` networks section should look like this:

```yaml
    networks:
      default:
      greenbone-scan-net:
        ipv4_address: 192.168.1.140
```

And ensure your `networks:` section at the bottom of the compose file includes:

```yaml
networks:
  default:
  greenbone-scan-net:
    external: true
```

### 5. Build and start

```bash
docker compose build netscan
docker compose up -d netscan
```

### 6. Open the UI

```
http://your-server-ip:3004
```

## OpenVAS scanner timeout

By default OpenVAS uses very long NVT timeouts that can cause scans to stall. Add the following to your `configure-openvas` service command in `compose.yaml` to set a sensible timeout:

```yaml
printf "table_driven_lsc = yes\nopenvasd_server = http://openvasd:80\nscanner_plugins_timeout = 120\n" > /mnt/openvas.conf
```

This reduces per-NVT timeout from the default 1800 seconds to 120 seconds, cutting overall scan time significantly.

## Known limitations

- **Scanning the host machine itself is not supported.** Due to macvlan networking, the container at `192.168.1.140` cannot communicate back to the host machine it runs on. Scan other devices on your network instead.
- **Scan times are 30–45 minutes** for a typical single host. This is inherent to how OpenVAS works — it is running a comprehensive test suite, not a quick port scan.
- **AI engine is fixed to Claude** in v1. A selectable AI engine (Claude / GPT-4 / Gemini) is planned for v2.
